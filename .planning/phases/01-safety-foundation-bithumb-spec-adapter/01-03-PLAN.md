# Plan 01-03: `core/`↔`broker/` import boundary via Import Linter + CI enforcement scaffolding + `bt` CLI capability dispatcher (Phase-1 verbs only)

**Phase:** 1 — Safety Foundation + Bithumb Spec Adapter
**Plan:** 03 of 4
**Slug:** import-boundary-cli-dispatcher
**Requirements covered:** SAFE-06, SAFE-02 (surfaces via `bt` CLI, per D-99)
**Estimated wave count:** 2
**Depends on:** 01-01 (uses `pyproject.toml`, package tree, `REGISTRY`, `validate()`), 01-02 (uses `reject_trade_credentials` hook in the validator, `bithumb_bot.core.money` docstring for `m0 selfcheck`'s risk-denominator print)

## Goal

The repository has (a) a live Import Linter forbidden-contract asserting `bithumb_bot.core` never imports `bithumb_bot.broker`, wired into pre-commit AND covered by a permanent negative-fixture test proving the contract *actually fails* on a violation; (b) a single `bt` console script with a stdlib-`argparse` two-level subparser dispatcher that validates every capability against `01-01`'s `validate()` before any handler / network / file / credential side effect can occur, and repeats the check inside every internal service function reachable via direct Python import (defense in depth per D-85); (c) functional Phase-1 handlers for `config validate --through gate1` and `m0 selfcheck` (the `m1` handlers land in plan 01-04); (d) reserved-verb handlers per D-87 that raise `NotImplementedError` on invocation without pretending to be functional (D-90).

## Success criteria

- `uv run lint-imports` exits `0` on the real committed tree.
- A permanently-committed scratch package under `tests/fixtures/import_linter_violation/badpkg/` contains `badpkg/core/leak.py: from badpkg.broker import x` and its own `.importlinter` config; a pytest test invokes `lint-imports --config <fixture_config>` via `subprocess.run` and asserts exit code is non-zero. The fixture is never mutated; the test never needs to "restore" the real tree.
- Pre-commit hook `id: import-linter` runs `lint-imports` project-wide with `pass_filenames: false, always_run: true, language: system`.
- `bt --help` and `bt --version` produce output and exit `0`, WITHOUT loading any credential, without calling `validate()`, and without instantiating `BithumbSecrets`.
- `bt bogus verb` exits non-zero with a message naming `UnknownCapabilityError` and does NOT touch the disk / network / env beyond argv parsing.
- `bt config validate --through gate1` succeeds against the committed `config/decisions/gate1.toml`, prints the resolved decisions summary (Gate-1 fields grouped by decision group), and exits `0`.
- `bt m0 selfcheck` prints resolved Gate-1 decisions, resolved key class (based on which credentials are set in the env — never printing values), and the five risk-denominator names from the `bithumb_bot.core.money` module docstring; exits `0` when Gate-1 is present.
- Every D-87 reserved verb (`bt m2 collect-observations`, `bt m2 calibrate-costs`, `bt m2 replay-known-answer`, `bt m4 evaluate-selection`, `bt m5 evaluate-module`, `bt freeze strategy`, `bt m6a verify-mock-broker`, `bt freeze final`, `bt holdout evaluate`) exits non-zero with a message stating the verb is reserved for a future phase; no side effect occurs.
- Every internal service function reachable via `from bithumb_bot.<module> import <fn>` calls `validate()` first as a defense-in-depth check.

### Task 01-03-05: `bt` CLI dispatcher — argparse two-level subparser + validate-before-dispatch

**Wave:** 2
**Type:** code
**Requirement(s):** SAFE-02 surface, D-85, D-89
**Threat(s):** T-1-03-02, T-1-03-04, T-1-03-05, T-1-03-06
**Dependencies:** 01-01-06 (registry), 01-01-07 (validator), 01-03-04
**tdd:** true

**Behavior:**
- `main(argv: list[str] | None = None) -> int` — entry point. Returns process exit code; `bithumb_bot.cli.main:main` is what `[project.scripts]` binds to.
- Argparse structure:
  - `bt` (root) with `--version`, `--help` handled natively by argparse.
  - Subparsers per D-86 verb: `config`, `m0`, `m1`. Each verb has its own sub-subparser: `config validate --through gate1`, `m0 selfcheck`, `m1 fetch-spec --market KRW-BTC`, `m1 verify-facts --bundle <path>`, `m1 verify-snapshot --snapshot <path>`.
  - Each D-87 reserved verb (`m2`, `m4`, `m5`, `freeze`, `m6a`, `holdout`) also gets a subparser + reserved sub-subverbs, but they all bind to the shared reserved handler.
- **Dispatch sequence** (documented in `dispatcher.py` module docstring):
  1. Special-case `--help` / `--version` / empty argv → argparse handles it, no capability lookup, no credential load, exit `0`.
  2. Parse argv → `(verb, subverb, remaining_args)`.
  3. Look up `REGISTRY[(verb, subverb)]`; **absent → print `unknown command` message to stderr, exit `2` (argparse convention for usage errors)**. Do NOT default to `CapabilityRequirements()` (D-89).
  4. Call `validate(capability=(verb, subverb))`.
  5. If not `result.ok`: print `refusal: <result.reason>` to stderr, exit `1`. No handler runs.
  6. Bind `structlog.contextvars.bind_contextvars(capability=..., command=..., invocation_id=uuid4())` — guarded by `try/except ImportError` until 01-04 lands.
  7. Dispatch to the registered handler with `remaining_args`.
- `main()` never catches unknown exceptions (they propagate → non-zero exit + traceback); it does catch `UnknownCapabilityError`, `ValidationError`, `Gate1LoadError`, `ProhibitedCredentialDetectedError`, `SecretsFileInsideRepoError`, `AmbiguousSecretsConfigurationError` and converts them to a clean stderr message + exit `1`.

**Description:**
Two files:
- `main.py` — one-line entry that calls `dispatcher.dispatch(sys.argv[1:])` and passes the return code through `sys.exit`.
- `dispatcher.py` — the argparse build + dispatch loop. Keep it entirely dependency-light (only stdlib + `bithumb_bot.config.*` + `bithumb_bot.cli.handlers.*` imports).

The dispatcher module MUST NOT import `bithumb_bot.broker` or `bithumb_bot.bithumb_spec.client` at top level — the client is imported lazily inside the `m1 fetch-spec` handler (which lives in 01-04); this preserves the "help/version does not load credentials" property AND avoids pulling httpx / structlog into the argparse-only code path.

**Files:**
- `+ src/bithumb_bot/cli/main.py`
- `+ src/bithumb_bot/cli/dispatcher.py`
- `+ src/bithumb_bot/cli/handlers/__init__.py`
- `+ tests/cli/__init__.py`
- `+ tests/cli/test_dispatcher.py`

**Automated verification:**
```
uv run pytest tests/cli/test_dispatcher.py -x -q
```

**Oracle:**
- `main(["--help"])` returns `0`; captured stdout contains usage text; no `BithumbSecrets` constructor was called (asserted via `mock.patch("bithumb_bot.secrets.settings.BithumbSecrets")` with `assert_not_called`).
- `main(["--version"])` returns `0`; captured stdout contains a version string.
- `main([])` returns `2` (argparse usage error) or `0` with help text — either is acceptable so long as no side effect occurs.
- `main(["bogus", "verb"])` returns non-zero; stderr mentions `unknown command`.
- `main(["m0", "selfcheck"])` calls `validate(("m0", "selfcheck"))` before dispatching (asserted via `mock.patch("bithumb_bot.config.validator.validate")` with a passing return); the handler is then invoked exactly once.
- When `validate()` is patched to return `ok=False`: handler is NEVER invoked; stderr contains `refusal:`.
- `main(["config", "validate", "--through", "gate1"])` recognizes the `--through gate1` flag.

### Task 01-03-07: `bt m0 selfcheck` handler — prints resolved decisions + key class + risk denominators

**Wave:** 2
**Type:** code
**Requirement(s):** SAFE-02 (per D-99), SAFE-07, D-86
**Threat(s):** T-1-03-02, T-1-03-04, T-1-03-06
**Dependencies:** 01-01-05, 01-01-07, 01-02-04, 01-02-07, 01-03-05
**tdd:** true

**Behavior:**
- Handler signature: `def handler(args: argparse.Namespace) -> int`.
- First statement: `_result = validate(("m0", "selfcheck"))` — defense in depth.
- Prints three sections to stdout:
  1. **Resolved Gate-1 decisions** — a compact summary sourced from `load_gate1(...)` (same as `config validate`, minus provenance-hash prefix).
  2. **Resolved key class** — computed from `BithumbSecrets()` presence:
     - Both `account_read_access_key` and `account_read_secret_key` set → `account_read`.
     - Either present but not both → `account_read (incomplete — missing <field>)`.
     - Neither set → `no credential loaded (public path only)`.
     - Trade cred present (either field) → **should have been caught by `validate()`'s hook** — but as defense in depth, the handler ALSO calls `reject_trade_credentials(...)` and refuses. Print the credential *class* only, never any part of the value (D-70).
  3. **Risk-denominator vocabulary** — the five terms (`planned_stop_loss`, `max_market_loss`, `max_operational_loss`, `position_fraction`, `risk_per_trade`) with their one-line definitions from `bithumb_bot.core.money.__doc__`.
- Never prints any credential value; never prints the resolved secrets-file path (even if configured).
- Returns `0` on success, non-zero if `validate()` refuses or `reject_trade_credentials` triggers.

**Description:**
`BithumbSecrets()` is constructed inside this handler (ephemerally per D-89 / Finding 4). The three-section format is the SAFE-02 success criterion from ROADMAP.md line 39 verbatim: "prints resolved decisions + key class + denominators."

Test-mode-only note: because `BithumbSecrets()` reads env vars, tests use `monkeypatch.setenv` / `monkeypatch.delenv` to control the credential class.

**Files:**
- `+ src/bithumb_bot/cli/handlers/m0_selfcheck.py`
- `+ tests/cli/test_handlers_m0_selfcheck.py`

**Automated verification:**
```
uv run pytest tests/cli/test_handlers_m0_selfcheck.py -x -q
```

**Oracle:**
- No creds in env → output contains `key class: no credential loaded`.
- Both account-read env vars set to sentinel non-empty values → output contains `key class: account_read`; sentinel values do NOT appear in stdout.
- Trade env var set → returns non-zero; stderr contains `refused` and the class name `trade`; the sentinel credential value does NOT appear anywhere in stdout or stderr.
