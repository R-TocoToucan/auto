# Plan 01-01: Config loader + Immutable Gate-1 Decision Register + capability-scoped startup validation (fail-closed)

**Phase:** 1 — Safety Foundation + Bithumb Spec Adapter
**Plan:** 01 of 4
**Slug:** config-loader-gate1-register-capability-validator
**Requirements covered:** SAFE-01, SAFE-02 (restructured per D-99)
**Estimated wave count:** 3 (Wave 0 + Waves 1–2)
**Depends on:** none

## Chosen package name

`bithumb_bot` — used by every PLAN in this phase. Matches the `BITHUMB_BOT_SECRETS_FILE` env-var convention in D-65; the `bt` console script (D-85) is a separate `[project.scripts]` entry, registered in plan 01-03. All Import Linter contract fields, all `from bithumb_bot.<x> import <y>` statements, and the pytest rootdir all use this name.

## Goal

The repository has (a) a `uv`-managed Python 3.11+ project skeleton with the tool-config skeleton every later plan wires into, (b) an immutable, hashable `Gate1Decisions` pydantic v2 model loaded from `config/decisions/gate1.toml` (only), (c) a central capability registry + `validate(capability) -> ValidationResult` function that fails closed on any missing/malformed/hash-mismatched Gate-1 input, and (d) a canonical `config_hash` manifest builder that Phase 3 (Gate 2) and Phase 5 (Gate 3 + FRZ-02) will extend without re-invention.

## Success criteria

- `uv sync` completes against the pinned lockfile; `uv run pytest -x -q --no-cov` runs (empty pass is acceptable at Wave 0).
- `config/decisions/gate1.toml` exists, contains only Gate-1 decisions from `01-CONTEXT.md` (D-40 numeric HTTP values; D-41 / D-42 fields present with `null` values + comment linking each field to its future gate; `provisional_engineering_notional_krw = "100000"` per D-09 / D-43), parses via `tomllib` in binary mode, and validates against `Gate1Decisions`.
- Attempting to mutate a loaded `Gate1Decisions` instance raises (`frozen=True`, D-58); any unknown TOML key raises (`extra="forbid"`, D-60); a TOML numeric literal in a decimal-bearing field raises (D-49 / Finding 3's `StrictDecimal`).
- `validate(("m0", "selfcheck"))` returns `ok=True` when `gate1.toml` is present and frozen; `validate(("m4", "evaluate-selection"))` returns `ok=False` with a reason naming the missing Gate-2 file (D-59 / D-88).
- `validate((unknown_verb, unknown_subverb))` raises `UnknownCapabilityError` (D-89 — capability requirements never default to an empty set).
- Every Phase-1 registry row (D-86) has an explicit unit test asserting its refusal/pass behavior; every reserved future verb from D-87 is registered but has a handler stub that raises `NotImplementedError` (D-90).
- `config_hash` manifest builder produces byte-identical output for byte-identical inputs (canonical JSON per D-76 / Finding 3).

### Task 01-01-05: TOML loader with binary-mode + hash-of-bytes provenance

**Wave:** 1
**Type:** code
**Requirement(s):** SAFE-01, D-58, D-61, D-62
**Threat(s):** T-1-01-01
**Dependencies:** 01-01-04
**tdd:** true

**Behavior:**
- `load_gate1(path: Path) -> tuple[Gate1Decisions, str]` returns the parsed frozen model + the hex SHA-256 of the file's exact bytes.
- Called with a text-mode-opened path would crash — the loader must use `open(path, "rb")` explicitly (matches D-58 / Finding 3's `tomllib` binary-mode gotcha).
- The returned hash is stable across repeated calls on the same file bytes; a single-byte mutation changes the hash.
- Missing file → `Gate1LoadError` with `path` context (not a bare `FileNotFoundError`).
- Malformed TOML → `Gate1LoadError` wrapping the `tomllib.TOMLDecodeError`.
- `status != "frozen"` → `Gate1LoadError` (D-60 fail-closed on unfrozen).

**Description:**
Implement `load_gate1` in `src/bithumb_bot/config/gate_loader.py`. It reads bytes with `pathlib.Path.read_bytes()`, hashes them via `hashlib.sha256(...).hexdigest()`, parses via `tomllib.loads(bytes.decode("utf-8"))` or `tomllib.load(io.BytesIO(bytes))`, constructs `Gate1Decisions(**data)`, and returns `(model, hex_digest)`. Do not re-serialize the parsed model to hash — hash the committed bytes directly (per Finding 3).

**Files:**
- `+ src/bithumb_bot/config/gate_loader.py`
- `+ src/bithumb_bot/errors.py` (add `Gate1LoadError`; other errors added by later plans)
- `+ tests/config/test_gate_loader.py`

**Automated verification:**
```
uv run pytest tests/config/test_gate_loader.py -x -q
```

**Oracle:**
- Positive: real `config/decisions/gate1.toml` loads, hash is 64 hex chars, model is frozen.
- Negative: missing file, malformed TOML, unquoted-decimal, unfrozen-status, `extra="forbid"` violation — each raises `Gate1LoadError` (structural) or `ValidationError` (schema) explicitly.
- Hash-stability: call twice, assert equal.
- Hash-sensitivity: mutate one byte in `tmp_gate1_toml`, assert hex differs.

**Done:**
- `load_gate1(Path("config/decisions/gate1.toml"))` succeeds on the committed file.

### Task 01-01-07: `validate(capability) -> ValidationResult` fail-closed validator

**Wave:** 2
**Type:** code
**Requirement(s):** SAFE-02 (per D-99)
**Threat(s):** T-1-01-01, T-1-01-02
**Dependencies:** 01-01-05, 01-01-06
**tdd:** true

**Behavior:**
- `validate(capability)` looks up `REGISTRY[capability]`; if absent, raises `UnknownCapabilityError` (D-89).
- If `row.gate1`: attempt `load_gate1(REPO_ROOT / "config/decisions/gate1.toml")`; on failure → `ValidationResult(ok=False, missing=("gate1",), reason=<load-error message>)`.
- If `row.gate2`: check for `config/decisions/gate2.toml`; if missing → `ValidationResult(ok=False, missing=("gate2",), reason="gate2 not yet frozen — Phase 3")`. Do NOT create it (D-56).
- If `row.gate3`: same for `gate3.toml` (Phase 5).
- Snapshot / cap / cred / human-auth requirements: for Phase-1 verbs only, snapshot and cap checks return `ok=True` (no snapshot required yet); cred check for `m1 fetch-spec` looks for `BITHUMB_ACCOUNT_READ_ACCESS_KEY` and `BITHUMB_ACCOUNT_READ_SECRET_KEY` env vars presence (never reads values); trade-cred rejection is stubbed here and wired to the real check in 01-02.
- `human_auth` for `m1 fetch-spec` (`INVOCATION_ONLY`) is a no-op — CLI invocation itself counts.
- `ValidationResult` is a frozen dataclass: `ok: bool`, `missing: tuple[str, ...]`, `reason: str | None`.

**Description:**
Implement `validate()` in `src/bithumb_bot/config/validator.py`. Import the registry from 01-01-06. Load only the gates a given capability requires (D-59). Never partial-succeed — the first failing prerequisite short-circuits and returns the specific `missing` tuple. Do NOT catch and swallow errors from `load_gate1` — a malformed Gate-1 must produce a specific, actionable `reason`, not a generic "gate1 missing".

**Files:**
- `+ src/bithumb_bot/config/validator.py`
- `+ tests/config/test_validator.py`

**Automated verification:**
```
uv run pytest tests/config/test_validator.py -x -q
```

**Oracle:**
- `validate(("m0", "selfcheck"))` with real committed `gate1.toml` present → `ok=True`.
