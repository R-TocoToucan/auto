## Goal

The repository has (a) `bithumb_bot.artifact` — a canonical-JSON + atomic-write + sidecar-hash + guard-against-overwrite primitive the spec-snapshot and every future immutable-artifact consumer will reuse; (b) `bithumb_bot.rate_limit.token_bucket` — an asyncio-native TokenBucket with an injectable monotonic clock, sufficient for three per-channel instances (`public_rest`, `private_rest`, `public_ws` connection); (c) `bithumb_bot.observability.logging` — structlog wired with `redact_secrets` (from 01-02) as a live processor; (d) `bithumb_bot.bithumb_spec` — an authenticated (JWT) `httpx.AsyncClient`-based read-only client for `/v1/orders/chance` with D-40 timeouts + retry-loop + `Retry-After` honoring; a canonical snapshot builder that emits the D-75 shape with per-capability status fields (D-83); a sanitization allowlist that strips authorization headers / cookies / signatures / nonces / access keys / account identifiers / balances / average-purchase prices / locked balances before any fixture is committed (D-77); and a `VERIFICATION.md` + `manifest.json` bundle generator (D-78, D-84); (e) three functional `bt m1` handlers replacing the 01-03 stubs, all fail-closed and defense-in-depth-guarded per D-85; (f) offline-only CI: no test in this plan makes a real network call to Bithumb (D-79).

## Success criteria

- `bithumb_bot.artifact.canonical_bytes({"b": 1, "a": 2})` returns byte-identical bytes across repeated calls; sorted keys; compact separators; UTF-8; trailing `\n`.
- `bithumb_bot.artifact.atomic_write(target, data)` creates a `.tmp-<pid>` file in the **same directory as `target`** (Windows same-filesystem correctness note in Finding 9), then `os.replace()`s it into place.
- `bithumb_bot.artifact.guard_against_overwrite` refuses to overwrite a snapshot whose sidecar hash matches the on-disk file (D-76 "never overwrite a previously consumed snapshot").
- `TokenBucket.acquire()` under a fake monotonic clock: (a) first N acquires up to `capacity` succeed without waiting; (b) the (N+1)th waits exactly `1/refill_rate` seconds of *simulated* time; (c) a real `asyncio.sleep` is never called for a non-zero duration in tests.
- The retry-loop honors an integer `Retry-After` header; does not retry on 400/401/403/404/422; retries up to `m1_spec_http_max_attempts` on 408/429/500/502/503/504 and on `ConnectTimeout`/`ReadTimeout`/`ConnectError`/`NetworkError` (D-40).
- JWT builder produces a Bearer token whose payload contains `access_key` and `nonce` (both non-empty), and — when query params are present — `query_hash` (128 hex chars for SHA-512) and `query_hash_alg = "SHA512"` (per Finding 6). The presence of a `timestamp` claim is a flagged Open Verification Item (#1); the JWT builder MUST include (or omit) a `timestamp` claim only per what the M1 `VERIFICATION.md` bundle attests — Wave 2 delivers the builder in a form parameterized on `include_timestamp: bool`, defaulting to `False` (documentation-only claim not confirmed by observation this pass), with a `# TODO(M1-verify)` docstring anchor. The `verify-facts` command refuses to advance if the `timestamp`-claim fact is `unresolved`.
- `fetch_spec()` (mocked via `httpx.MockTransport`) produces (i) a sanitized fixture under `tests/fixtures/bithumb/sanitized/orders_chance/<ts>.json` containing only the D-77 allowlist fields, (ii) a candidate canonical snapshot at `artifacts/spec_snapshots/KRW-BTC/<YYYYMMDDTHHMMSSZ>.json` + sidecar, and (iii) a `verification/bithumb/<ts>/VERIFICATION.md` scaffold + `manifest.json`.
- Snapshot never re-queried mid-simulation: the loader function (which Phase 2's simulator will use) accepts a snapshot ONLY when its sidecar hash matches + schema version matches + market matches + every required `verification_status` key is present and non-`unresolved_until_M6B` (D-79, D-80).
- Per-capability status fields (D-83) are present in the snapshot: at minimum `general_fee_rate`, `market_buy_fee_reservation`, `rounding_rejection_behavior`, `live_order_acceptance`. Values are conservative defaults + `unresolved_until_M6B` where appropriate.
- `bt m1 fetch-spec --market KRW-BTC` (offline test with mock transport) writes the three-artifact bundle; `bt m1 verify-snapshot --snapshot <path>` accepts a valid snapshot and refuses a tampered one; `bt m1 verify-facts --bundle <path>` refuses a bundle with an `unresolved` mandatory fact.
- Structlog is wired at CLI entry (`main()` binds `capability`, `command`, `invocation_id`); the `redact_secrets` processor is in the chain; no `SecretStr` value has ever been observed in captured log output across the test suite.
- Every internal service function (`fetch_spec`, `write_snapshot`, `load_snapshot`, `verify_facts_bundle`) calls `validate(...)` first (defense in depth per D-85).

### Task 01-04-01: `artifact/canonical.py` + `artifact/timestamps.py` — canonical JSON, atomic write, sidecar, timestamps

**Wave:** 1
**Type:** code
**Requirement(s):** SPEC-04
**Threat(s):** T-1-04-03, T-1-04-07, T-1-04-09
**Dependencies:** 01-01-01
**tdd:** true

**Behavior:**
- `canonical_bytes(obj) -> bytes`: `json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False).encode("utf-8") + b"\n"` per Finding 9.
- `sha256_hex(data: bytes) -> str`: `hashlib.sha256(data).hexdigest()`.
- `atomic_write(target: Path, data: bytes) -> None`: creates `tmp = target.with_name(f"{target.name}.tmp-{os.getpid()}")` (same directory as target — Windows same-filesystem correctness), `tmp.write_bytes(data)`, `os.replace(tmp, target)`.
- `sidecar_line(hex: str, filename: str) -> str`: `f"{hex}  {filename}\n"` (two spaces).
- `write_with_sidecar(target: Path, data: bytes) -> tuple[Path, Path]`: writes data + `{target}.sha256` sidecar atomically.
- `guard_against_overwrite(target: Path, sidecar: Path) -> None`: if target does not exist → return. If exists AND sidecar exists AND sidecar-recorded hash equals current-file hash → raise `SnapshotAlreadyConsumedError(target)`. If exists AND sidecar-hash does NOT match current-file hash → rename target to `_corrupt_{utc_timestamp()}_{target.name}` and raise `CriticalCorruptionAlert(corrupt_path)`.
- `utc_now() -> datetime`: `datetime.now(timezone.utc)`.
- `utc_timestamp() -> str`: `utc_now().strftime("%Y%m%dT%H%M%SZ")` — no colons (D-74).

**Description:**
Two small modules; ~120 lines total. Errors live in `bithumb_bot.errors`. Neither module imports anything from `bithumb_spec/` (they're generic primitives — Phase 2's Parquet-store integrity check will reuse them).

**Files:**
- `+ src/bithumb_bot/artifact/__init__.py`
- `+ src/bithumb_bot/artifact/canonical.py`
- `+ src/bithumb_bot/artifact/timestamps.py`
- `~ src/bithumb_bot/errors.py` — add `SnapshotAlreadyConsumedError`, `CriticalCorruptionAlert`, `SidecarHashMismatchError`
- `+ tests/artifact/__init__.py`
- `+ tests/artifact/test_canonical.py`
- `+ tests/artifact/test_atomic_write.py`
- `+ tests/artifact/test_guard_against_overwrite.py`
- `+ tests/artifact/test_timestamps.py`

**Automated verification:**
```
uv run pytest tests/artifact -x -q
```

**Oracle:**
- `canonical_bytes({"b": 1, "a": 2}) == canonical_bytes({"a": 2, "b": 1})` (key-order independent).
- Hypothesis: for random JSON-serializable dicts (int/str/list/nested-dict values), two calls return equal bytes.
- Trailing `\n`: assert `canonical_bytes(x).endswith(b"\n")`.
- `atomic_write` places the temp file in `target.parent` (asserted by mocking `Path.write_bytes` and inspecting the path passed).
- `guard_against_overwrite`: fresh target → no error; existing + matching sidecar → raises `SnapshotAlreadyConsumedError`; existing + mismatched sidecar → renames + raises `CriticalCorruptionAlert`.
- `utc_timestamp()` matches `^\d{8}T\d{6}Z$` — no colons.

**Done:**
- All modules mypy `--strict` clean.

### Task 01-04-02: `rate_limit/token_bucket.py` — asyncio TokenBucket with injectable clock

**Wave:** 1
**Type:** code
**Requirement(s):** SPEC-05
**Threat(s):** T-1-04-05
**Dependencies:** 01-01-01
**tdd:** true

**Behavior:**
- `TokenBucket(capacity: float, refill_rate: float, *, monotonic: Callable[[], float] = time.monotonic)` — clock is injectable so tests can pass a `fake_monotonic_clock` (from 01-01's conftest).
- `await acquire(n: float = 1.0) -> None`: acquire `n` tokens or `await asyncio.sleep(delay)` for enough time to refill.
- Refill: `elapsed = now - last_refill; tokens = min(capacity, tokens + elapsed * refill_rate)`.
- Concurrent-safe via `asyncio.Lock`.
- Tests use a `fake_monotonic_clock` fixture that returns a mutable `[float]` closure; each `tick(dt)` call advances it; the test then patches `asyncio.sleep` with an `AsyncMock` that records durations without actually sleeping, so the entire test suite completes in milliseconds even for "sleep 10 seconds" scenarios.

**Description:**
Per Finding 7. Do NOT hardcode numeric capacities / refill rates — those are Open Verification Item #3. This module's tests use sentinel values that make the arithmetic obvious (e.g. `capacity=2, refill_rate=1.0` → 1 token/sec).

**Files:**
- `+ src/bithumb_bot/rate_limit/__init__.py`
- `+ src/bithumb_bot/rate_limit/token_bucket.py`
- `+ tests/rate_limit/__init__.py`
- `+ tests/rate_limit/test_token_bucket.py`

**Automated verification:**
```
uv run pytest tests/rate_limit -x -q
```

**Oracle:**
- Initial full bucket: `capacity=2, refill_rate=1.0` → first two `acquire()` calls succeed without any sleep.
- Third acquire waits `1.0 s` of *simulated* time; real `asyncio.sleep` mock is called exactly once with `1.0`.
- Advance clock 2 seconds → bucket refills to `min(capacity, elapsed*refill_rate)` = 2; two more acquires succeed without sleep.
- No `pytest.mark.timeout` needed — no real sleeps.
- `acquire(n=3)` when `capacity=2, refill_rate=1.0` — waits `1.0 s` (from 2 tokens → needs 1 more, at 1 token/s), then acquires.

**Done:**
- Test runtime < 1 second total.

### Task 01-04-04: `bithumb_spec/jwt_auth.py` — JWT builder with `include_timestamp` flag + Open Verification Item #1 anchor

**Wave:** 2
**Type:** code
**Requirement(s):** SPEC-01
**Threat(s):** T-1-04-01, T-1-04-08
**Dependencies:** 01-04-01
**tdd:** true

**Behavior:**
