# Plan 01-02: Three-class key policy + secret loading + `Decimal` money type + AST-based float-literal lint + risk-denominator vocabulary

**Phase:** 1 — Safety Foundation + Bithumb Spec Adapter
**Plan:** 02 of 4

**Requirements covered:** SAFE-03, SAFE-04, SAFE-05, SAFE-07

## Goal

The repository (a) enforces the three-class API-key policy — the four documented `BITHUMB_ACCOUNT_READ_*` and `BITHUMB_TRADE_*` credentials are the only credential fields, no withdrawal credential exists anywhere, trade credentials are rejected pre-M6B; (b) loads secrets from process env only (or from an explicitly-configured outside-repository external file), symlink-safely rejects any resolved in-repo path, detects ambiguous mixed-source configuration; (c) enforces exact-decimal arithmetic project-wide via a repo-owned Python-AST checker running in pre-commit AND CI; (d) documents the risk-denominator vocabulary as a `NewType`-based module with docstrings the sizing pipeline will later consume.

## Success criteria

- `python -m tools.decimal_ast_check src tests tools` returns non-zero when at least one positive fixture (`Decimal(0.1)`, `Decimal(-0.1)`, `Decimal(+0.1)`, `decimal.Decimal(0.1)`, `dec.Decimal(0.1)`, `D(0.1)`) exists in the scanned tree, and returns zero over the real committed tree.
- The AST checker never flags a negative fixture (`Decimal("0.1")`, `Decimal(1)`, `Decimal(-1)`, `Decimal(some_string_var)`).
- Pre-commit hook `decimal-float-literal-check` runs on every commit; CI runs the same check across `git ls-files '*.py'`.
- `BithumbSecrets` model exposes exactly four credential fields (no `withdrawal_*`); attempting to load `BITHUMB_TRADE_ACCESS_KEY` from env raises `ProhibitedCredentialDetectedError`, and the exception's message contains only the credential *class* (`trade`), never the value (D-70).
- Setting `BITHUMB_BOT_SECRETS_FILE` to a path that resolves inside the repo (directly or via symlink) raises `SecretsFileInsideRepoError` (per D-65).
- Defining the same credential in both env and the external secrets file with different values raises `AmbiguousSecretsConfigurationError` (D-66 rule 3).
- `SecretStr` fields render as `***` under `repr(model)`, `str(model)`, and `model.model_dump()` (JSON mode included); a custom `structlog` `redact_secrets` processor is exported and unit-tested.
- `bithumb_bot.core.money` exports `Money`, `Qty`, and the five risk-denominator `NewType`s (`PlannedStopLoss`, `MaxMarketLoss`, `MaxOperationalLoss`, `PositionFraction`, `RiskPerTrade`), each with a module-level docstring section and doctring on the type binding.
- Rounding helpers pass property tests at exact tick, tick-below, tick-above, zero, and the largest supported value; direction is chosen per D-49 ("never round up a user-controlled spend/sell quantity").

### Task 01-02-01: Repo-owned Decimal-from-float AST checker

**Wave:** 1
**Type:** code
**Requirement(s):** SAFE-05
**Threat(s):** T-1-02-04
**Dependencies:** 01-01-01 (needs package tree + `.pre-commit-config.yaml` skeleton)
**tdd:** true

**Behavior:**
- CLI: `python -m tools.decimal_ast_check <path>...` walks each `<path>` (files and directories, recursive) for `*.py`; prints each finding on its own line as `<path>:<lineno>:<col_offset>: DECIMAL_FROM_FLOAT` and exits `1` if any finding, else exits `0`.
- Alias tracking per Finding 2: build a per-file dict of module aliases (`import decimal`, `import decimal as dec` → `{"decimal", "dec"} -> "decimal"`) and name aliases (`from decimal import Decimal`, `from decimal import Decimal as D` → `{"Decimal": "decimal.Decimal", "D": "decimal.Decimal"}`); walk `Call` nodes; only flag when the callable resolves through the alias table to `decimal.Decimal`.
- Unwrap **one** level of `UnaryOp(UAdd|USub, ...)` before checking `Constant`; flag if the inner value is `float` or `complex`.
- Must NOT flag `Decimal("0.1")`, `Decimal(1)`, `Decimal(-1)` (`UnaryOp(USub, Constant(int))` — inner is `int`), `Decimal(some_string_var)` (arg is `Name`, statically unknown — deliberate false-negative per D-72 scope).
- Syntax error in a file: print `<path>: SYNTAX_ERROR: <message>` on stderr and exit `2` (not `0`, not `1`). Do NOT silently pass a file that failed to parse.
- Explicit non-goals (documented in the module docstring): re-binding an alias mid-file, cross-file inference, dynamic-argument type inference.

**Description:**
Implement per Finding 2. Pure stdlib — `ast`, `pathlib`, `sys`, `argparse`. ~80–120 lines. Do NOT use Ruff plugin infrastructure (D-73). Keep the alias-tracker in a single `ast.NodeVisitor` subclass or two small helpers; keep the module dependency-free so it can run from a fresh clone before `uv sync` if needed.

**Files:**
- `+ tools/__init__.py`
- `+ tools/decimal_ast_check.py`

**Automated verification:**
```
uv run python -m tools.decimal_ast_check tools src
```

**Oracle:**
- Exit code 0 when run over the real committed tree (no violations expected — the tree is greenfield).
- The alias table logic is unit-tested indirectly via the fixture-suite test in 01-02-02; this task is not blocked on those tests, but 01-02-02 asserts real behavior.

**Done:**
- Module runs from `python -m tools.decimal_ast_check` (uses `__main__` guard) AND has an `argparse`-based `main()` for testability.
- Module docstring explicitly lists what the checker does NOT try to detect (per D-72 scope note + Finding 2 explicit non-goals).

### Task 01-02-05: Secrets bootstrap: symlink-safe path check, ambiguous-mix detection, trade-cred rejection

**Wave:** 2
**Type:** code
**Requirement(s):** SAFE-04, SAFE-03
**Threat(s):** T-1-02-01, T-1-02-02, T-1-02-03, T-1-02-05
**Dependencies:** 01-02-04
**tdd:** true

**Behavior:**
- `load_secrets(repo_root: Path) -> BithumbSecrets`:
  1. If `BITHUMB_BOT_SECRETS_FILE` env var is set: `resolved = Path(raw).resolve(strict=True)` → if `resolved.is_relative_to(repo_root.resolve(strict=True))` raise `SecretsFileInsideRepoError(resolved)`.
  2. Parse the file's raw `KEY=value` lines (no shell semantics — no export, no substitution, no quoting nuance beyond a simple `key = value` split on the first `=`). Collect keys as a `dict[str, str]`.
  3. For every credential key present in BOTH os.environ and the parsed file dict: if the values differ → `AmbiguousSecretsConfigurationError(key)` (D-66 rule 3).
  4. Construct `BithumbSecrets(_env_file=resolved, _env_file_encoding="utf-8")` if file was provided, else `BithumbSecrets()` (env only).
  5. Return the settings.
- On Windows, `Path.resolve(strict=True)` normalizes both drive letters and case before the containment check.
- `reject_trade_credentials(settings: BithumbSecrets) -> None` — raises `ProhibitedCredentialDetectedError(credential_class="trade")` if `settings.trade_access_key is not None or settings.trade_secret_key is not None`. The exception's `str()` contains only the literal `trade`, never any part of the value (D-70).

**Description:**
Per Finding 4. `errors.py` grows `SecretsFileInsideRepoError`, `AmbiguousSecretsConfigurationError`, `ProhibitedCredentialDetectedError`. Each error takes only the class/key name — no `SecretStr` or credential-value argument shall be storable on the exception.

Wire `reject_trade_credentials(load_secrets(REPO_ROOT))` into 01-01's `validate()`: for every capability with `trade_cred_prohibited=True` (which is every registered capability per D-97), call the rejector before returning `ValidationResult(ok=True)`. On rejection, return `ValidationResult(ok=False, missing=("trade_credential_prohibited",), reason="trade credential class detected in environment — refused (D-68/D-97)")` instead of raising, so the CLI dispatcher prints a clean refusal.

### Task 01-02-08: `bithumb_bot.core.rounding` — direction-aware quantize helpers

**Wave:** 2
**Type:** code
**Requirement(s):** SAFE-05, SPEC-03
**Threat(s):** T-1-02-04
**Dependencies:** 01-02-07
**tdd:** true

**Behavior:**
- `quantize_krw_amount_down(amount: Decimal, unit: Decimal) -> Decimal` — quantize DOWN to `unit`; asserts `unit > 0`; result is `Decimal`.
- `quantize_volume_down(volume: Decimal, step: Decimal) -> Decimal` — quantize DOWN to `step`.
- `quantize_price_tick_up(price: Decimal, tick: Decimal) -> Decimal` — quantize UP to `tick` (adverse for buy fills per D-50).
- `quantize_price_tick_down(price: Decimal, tick: Decimal) -> Decimal` — quantize DOWN to `tick` (adverse for sell fills per D-51).
- Never uses `float` (checker enforces).
- Property tests (hypothesis):
  - Exact multiple of unit: `q(k*unit, unit) == k*unit` for any positive integer `k` and positive `Decimal` `unit`.
  - Below-boundary: `q(k*unit - epsilon, unit) == (k-1)*unit` for DOWN helpers, `== k*unit` for UP helpers.
  - Zero: `q(Decimal(0), unit) == Decimal(0)`.
  - Above-boundary: `q(k*unit + epsilon, unit) == k*unit` for DOWN helpers, `== (k+1)*unit` for UP helpers.
  - Idempotence: `q(q(x, u), u) == q(x, u)`.
- These helpers do NOT yet know Bithumb's specific tick / step / KRW-amount unit — those come from the M1 spec snapshot (01-04). This task ships the primitives + property tests; wiring to spec-snapshot values happens in Phase 2 (M2) per the phase-boundary rules.

**Description:**
Implement with `Decimal.quantize(exp, rounding=<ROUND_DOWN | ROUND_UP>)` after normalizing the exponent to match `unit`'s scale. Guard against non-positive `unit` / `step` / `tick`. Return only `Decimal` — never coerce to `Money` / `Qty` (that wrapping is caller's responsibility so the helper is reusable across contexts).

**Files:**
- `+ src/bithumb_bot/core/rounding.py`
- `+ tests/core/test_rounding.py`

**Automated verification:**


**Oracle:**
- All hypothesis strategies use `Decimal`-generating strategies (`hypothesis.strategies.decimals(min_value=..., max_value=..., allow_nan=False, allow_infinity=False, places=<n>)`) — never `hypothesis.strategies.floats`.
- Boundary tests pass at exact multiples, one-unit-below, one-unit-above, zero.
- Adversarial direction test: `quantize_price_tick_up(price=Decimal("1.9"), tick=Decimal("1"))` → `Decimal("2")` (up); `quantize_price_tick_down(price=Decimal("1.9"), tick=Decimal("1"))` → `Decimal("1")` (down).
